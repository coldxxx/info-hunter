## 回退方式

回退前先保留正在进行的本地修改；先用 `git show <commit>` 审查目标。可用 `git switch -c review/baseline baseline/first-commit` 建立基线检查分支。首次基线不含本次新增的验证脚本，因此历史代码的检查需沿用该记录中的隔离环境方式。

要撤销某个结构批次，按依赖逆序使用 `git revert <commit>` 并处理相邻批次依赖，验证后再考虑实例切换。Git 回退仅处理源码；数据库、备份、私有配置、登录态及其它忽略文件独立保留，不用源码回退代替数据库恢复，不使用清理忽略文件的操作。正式服务切换与数据库恢复按 [运维说明](../operations.md) 单独安排。
