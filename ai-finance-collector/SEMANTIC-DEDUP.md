# 本地 Qwen 语义去重

入口：<http://127.0.0.1:43187/?view=semantic>。系统使用 Qwen3-Embedding-0.6B Q8_0 做跨语言相似资料检索，使用机器上已有的 Qwen3.6-27B MLX 4bit 判断资料关系。模型由 LM Studio 提供，本机推理，不需要 MCP。

## 使用

1. 保持 LM Studio 本地服务和模型运行。重启电脑后，在本目录执行 `python3 start_semantic_models.py`。脚本使用已经下载的模型，不重复加载已就绪的模型；判断模型标识为 `radar-semantic-judge`，向量模型标识为 `radar-semantic-embedding`。模型服务默认端口 1234。
2. 打开“语义去重”，检查模型连接，开启处理。首次运行先建立历史资料的向量索引，再判断相似资料。新资料、正文提取和转录更新会自动排队；服务重启恢复任务。
3. 在资料对中核对两边的原始标题、摘要、引用依据及模型理由，选择关系后保存。确认“重复信息”会折叠信息流；其他关系保留独立文章。当前主题的列表只显示两篇都属于该主题的资料对。
4. 可以在文章详情将入口拆为独立文章。拆分会阻止后台再次自动合并。在“最近操作”撤销复核或拆分；有后续操作时先撤销后续操作。
5. 信息流的“展开所有入口”可显示每条原始记录。收藏、笔记和核验状态保留在各自的原始记录上，收藏或主题筛选在分组前进行。

资料清理后无法撤销涉及已清理资料的历史操作。正文变化会使旧的模型判断和人工重复标签失效，等待重新分析；人工拆分的约束仍保留。

## 判断策略

关系包括重复、同事件有增量、同事件有冲突、主题相关、不相关、信息不足。Embedding 的高相似度只负责召回候选，不直接决定重复。默认检索范围为发布日期相差 14 天，每篇最多 5 个候选，相似度下限 0.72；同一主题也可能是不同事件。

判断使用原文，不使用翻译和用户笔记作为身份依据。每条结论保存两边的内容指纹、模型配置、检索相似度、结构化理由、原文引文和策略版本。未能在所给原文中找到引用、重复结论与增量/冲突字段矛盾、数字或版本不一致、摘要太短、正文超过判断窗口，都会降为“信息不足”。模型目前最多检查正文前 6500 个字符，超过窗口的资料不能自动确认全文重复。

现有 URL 去重和保守的新闻索引标题分组继续工作。模型主要分析这些分组之间的关系；旧规则形成的组可以通过详情手动拆分。自动分组要求组间所有资料对都有已验证的重复边，避免 A≈B、B≈C 就推导 A≈C。人工确认则明确合并两边所在的组，并服从既有拆分约束。

## 运行与限制

SQLite 持久化向量缓存、待处理任务、关系、复核标签、拆分约束和撤销日志。更新标题、摘要或正文后重算；修改模型、检索范围、阈值或策略后重新排队。模型请求在数据库写事务之外执行。单个后台进程持有文件锁，失败按退避策略重试，3 次失败后可在页面重试。

默认最近 24 小时最多 300 次资料对判断，包含失败请求。达到预算后自动等待恢复，页面显示用量及恢复时间。该限制不限制首次向量索引的请求数。暂停后当前请求可能完成收尾。大规模历史回填会逐步进行，不会立即完成。

当前采用人工复核模式。模型自报分数不是测得的正确率。自动折叠默认关闭，只有当前模型和阈值通过独立人工标注验证后才可启用：至少 100 对不重复的样本对，含至少 50 对非重复，自动动作的重复精确率 ≥99%、召回率 ≥80%。这里“独立”指样本对不重复；仍需人工确保样本代表真实资料，避免只选简单案例。更换模型、阈值或策略会失去已有验证资格。

27B 判断模型文件约 16 GB，32768 上下文的单路推理还需要额外运行内存，本机当前使用 48 GB 内存。LM Studio 必须持续运行；容器启动不负责启动宿主机模型服务。默认本机 HTTP 地址，容器内部通过 `host.docker.internal:1234/v1` 访问。设置中的模型地址留空即可。更换模型权重时也应更换模型标识，确保缓存和验证资格失效。

## 验证与维护

已完成 166 项后端回归测试、前端类型检查和构建。真实 Qwen 的 8 对合成边界样本涵盖中英改写、同语改写、版本差异、数字冲突、独立测试增量、仅标题、无关主题及否定冲突；系统关系分类与预设标签一致。默认 0.98 自动阈值下两对重复均未触发自动折叠，说明该阈值尚不能启用自动模式。这是功能联调结果，不是生产准确率评估。另已实际验证每篇 7031 字符的中文正文可完成推理，截断防护将其保留为信息不足。网页的确认重复、折叠展示、拆分、撤销、展开原始入口、关系筛选和原文展开已在隔离环境验证。

重跑合成样本：

```sh
python3 verify_semantic.py
```

结果保存至 `verification/qwen-smoke.json`，使用临时数据库，不修改真实资料和自动模式资格。启动脚本只检查模型是否加载；实际推理检查用此验证命令。

在页面导出人工复核样本后，用真实独立样本进行评估：

将文件放进 `data/`，通过正在运行的容器访问资料库：

```sh
docker compose exec observatory python radar.py semantic-evaluate --evaluation-file /data/semantic-reviewed-pairs.json
docker compose exec observatory python radar.py semantic-status
```

JSON 为数组，每项有 `left`、`right`（至少 `title`，以及 `excerpt` 或 `body`）及 `expected`（六种关系之一）。重复或逆序的同一资料对会被拒绝。评估依据实际自动阈值与所有防护后的动作计算精确率、召回率，保存结果后页面显示资格；评估不改变分组、不训练模型。先暂停后台分析再做批量评估。容器运行期间，数据库备份、诊断和评估都应在容器内执行，避免宿主机和 Docker 同时访问 SQLite 的 WAL 文件。仅在容器停止时使用本机 `radar.py` 访问正式资料库。

部署前数据库备份保存在 `backups/radar-pre-semantic-deploy-*.sqlite3`，旧容器镜像标签为 `ai-industry-observatory:pre-semantic-20261005`。正常重新构建仍使用父目录原有的 Dockerfile 和 compose.yaml。
