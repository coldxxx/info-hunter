## 数据与操作

- `data/radar.sqlite3`：本地 SQLite 数据库，含原始标题、来源提供的短摘要、链接、发布时间、首次采集时间、来源命中记录、标签、收藏、笔记与核验状态。
- `sources.json`：25 个入口的注册表。`adapter=rss` 为 RSS/Atom，`x` 为官方 X recent search，`manual` 仅手动录入，不能算作自动覆盖。修改后重启服务或执行下一次 CLI 命令加载。
- `backups/`：使用 SQLite backup API 生成的一致性快照。每轮采集结束或点击“备份”生成；不会自动删除旧快照。仅为同机快照，不是异地备份。建议将快照和配置另备份到外置盘/异地存储。

```sh
python3 radar.py collect                 # 所有已启用来源
python3 radar.py collect --source nvidia # 单一来源
python3 radar.py status                  # 查看覆盖和失败原因
python3 radar.py backup                  # 一致性快照
python3 -m unittest -v                   # 行为测试
```

数据库按标准化 URL 去重，并保存各采集入口的命中关系。Google 索引 URL 与直接原文 URL 可能仍重复，同一事件的不同报道不会自动合并。日期解析失败保留未知，不编造日期；缺失发布时间的内容按首次采集时间排序。

## 恢复

先停止采集服务。选择一个快照，在临时目录用 `sqlite3` 打开并执行 `PRAGMA integrity_check`，确认 `ok` 并核对笔记。将现有 `data` 文件夹改名保留，再创建 `data` 文件夹，把快照复制为 `data/radar.sqlite3`，重启服务。不要将旧的 WAL/SHM 文件与恢复快照混用。
