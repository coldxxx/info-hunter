# 全局信息源与共用采集适配器

主题保存关注关系、关键词、排除词、地区、内容侧重和兴趣偏好。信息源保存入口地址、适配器及来源参数；一份来源配置可以被所有主题关注。新增来源保存在全局来源库，主题通过 `watch_sources` 引用来源 ID，不复制来源或采集实现。

来源管理默认展示全局来源库，支持筛选当前主题未关注的来源、选择多行和批量加入。已有绑定重复加入时保留原收录规则。移出一个主题只移除绑定，其他主题的绑定、来源配置和历史归档保留。暂停来源作用于所有主题。

## 同类型论坛复用逻辑

`capture.py` 登记共用适配器，通过 `read` 分派采集。来源类型（论坛、新闻、博客、视频等）用于内容分类，采集方式由实际入口协议或平台决定。

| 适配器 | 多个来源分别配置 | 共用实现 |
| --- | --- | --- |
| RSS / Atom | 各论坛或博客的 `feed_url` / `url` | 公开 URL 验证、HTTP 读取、RSS/Atom/RDF 解析 |
| Reddit API | 各 Reddit 板块的 `subreddit` | OAuth、限流、读取新帖子、字段映射 |
| X API | 各来源的 `query` | 授权开关、请求额度、限流、帖子字段映射 |
| 浏览器辅助 | 各论坛的网页地址 | 人工读取与导入流程，已有平台的链接与字段校验 |
| 手动录入 | 来源网址与摘录 | 待接入状态及资料录入流程 |

例如，两个公开 RSS 论坛共用 RSS 适配器；Reddit 的多个板块共用 Reddit 适配器。同类型适配器输出统一的候选字段：标题、链接、摘要、发布时间、发布方，再进入 `radar.py` 的主题筛选、标准化、去重、归档、结果记录和备份。

不同平台的接口结构、授权和分页边界由各自适配器处理。浏览器辅助不等于自动网页抓取；当前批次导入只支持已登记的 Reddit、X、雪球来源。尚未接入的论坛保留入口与状态，不标记为自动采集成功。

后台采集把所有启用主题的绑定来源按来源 ID 合并，同一来源每轮只进入一次采集流程，调度采用启用主题中最高兴趣分。主题专用新闻检索源仍可共享，但复用时保留已有检索参数；各主题再应用自己的筛选规则。

## 删除与详情中的连接

来源列表每行末尾有删除按钮，来源详情标题旁也提供「删除来源」。确认框显示来源名称和受影响的主题；删除会从全局库隐藏来源，解除所有主题绑定并停止后续采集。后台正在读取的来源在入库前再次检查删除标记，迟到结果不会写入。

历史文章、命中记录、正文与媒体、译文、收藏、笔记和核验状态保留。归档仍显示原始来源名称。注册表保留删除标记，默认来源不会因重启或主题保存自动恢复；用户明确重新添加同一链接时恢复原来源 ID，并只绑定本次指定的主题。共享账号登录会话保留，其他来源可继续使用。

「平台连接、发现播客、公众号与文章、导入 OPML」属于来源管理主页面的全局工具。来源详情单独使用 `SourceConnection`：普通新闻 RSS 不显示账号面板；具体 X 作者只显示 X 连接，Reddit 板块只显示 Reddit 连接；博客只提供本站的会员正文绑定。已绑定时只显示该来源关联的连接，不显示其他平台或其他博客账号。

## 页面 URL 状态

前端 `lib/url-state.ts` 使用查询参数记录可导航状态，并响应浏览器前进、后退。切换页面、主题或打开详情会建立历史记录；输入筛选条件和翻页更新当前记录。

| 状态 | URL 参数 |
| --- | --- |
| 页面与关注主题 | `view`、`watch`（默认信息流与 Coding 与 Agent） |
| 信息流与收藏筛选 | `q`、`region`、`topic`、`kind`、`source`、`since`、`direction`、`original`、`collapse`、`offset` |
| 打开的资料与来源详情 | `article`、`source_detail` |
| 来源列表筛选、排序、范围、分页 | `src_*` |
| 新增来源、主题编辑 | `add_source`、`edit_topic`、`draft_profile` |
| 全局工具、播客搜索与预览 | `platform_panel`、`podcast_q`、`podcast_feed` |
| 语义去重筛选与分页 | `semantic_status`、`semantic_relation`、`semantic_offset` |

刷新会重新读取本地数据并恢复上述状态。账号凭据、未保存的笔记、复核备注及录入表单正文不写入 URL。资料详情按 ID 独立读取，不依赖当前列表页。

## 接口

- `GET /api/sources?all=1&watch_id=…`：完整全局库，以及每个来源的关注主题与当前主题绑定状态。
- `POST /api/watch-sources`：提交 `watch_id`、`source_ids`（1–100 项）和可选 `include_all`，只增加绑定；整批验证后写入，不覆盖已有绑定规则。
- `POST /api/source`：识别入口并加入全局库；显式 `watch_id: null` 可仅保存来源。新主题重复提交已有来源不会替换已验证的共享采集配置；待接入的用户来源可由验证成功的 RSS 升级。
- `POST /api/source-delete`：提交 `source_id`，全局移除来源并保留归档；重复删除返回成功，未知来源或外站写入会被拒绝。
- `GET /api/articles?id=…`：精确读取单条资料及同文入口，恢复 URL 中的资料详情；返回保留的来源名称。
- `GET /api/source-detail?id=…&watch_id=…`：返回共用策略、实际适配器、来源参数、实现流程、共享主题和采集记录；只读，不触发网络采集。
